# v0.3.0 release notes — standalone Windows investigator

**Investigator** is a local-first AI security investigation agent for Windows that turns
security signals into evidence-grounded incident investigations. v0.3 makes the Windows
event logs of the local computer the primary telemetry source; Wazuh is an optional
integration. Details: [CHANGELOG.md](CHANGELOG.md). Raw outputs:
[`docs/validation/v0.3/`](docs/validation/v0.3/).

## Go/no-go status

*Can the existing investigation engine perform useful, evidence-grounded investigations
directly against real Windows telemetry without Wazuh or another SIEM?*

**Not yet answered.** The v0.3 development environment was Linux without a Windows
host. What *is* established: the unchanged engine investigates Windows-shaped
telemetry end to end (signals → tools → evidence → gated verdict) when the events are
supplied as Windows event XML. What is *not* established: that the live reader returns
that XML on a real Windows 11 machine, and how a real local model behaves on real
telemetry. The procedure to answer it is ready: `docs/validation/v0.3/REAL_WORLD_PROCEDURE.md`.

## Implemented but NOT verified

- **Live Windows Event Log reader** (`PyWin32Reader`: `EvtQuery`/`EvtNext`/`EvtRender`,
  error mapping for access denied / channel not found, elevation check). Never executed.
  The 4 live Windows integration tests are gated (`SOCI_IT_WINDOWS=1`) and were skipped.
- **Real-world scenarios RW-01…RW-05**: NOT RUN (`docs/validation/v0.3/RESULTS.md`).
- **Channel permissions** in SECURITY.md are expected Windows defaults, not observations.
- **Event XML fidelity**: the samples follow documented schemas but were authored; field
  quirks of real Sysmon/Defender versions may differ.
- **Ollama**: not installed here; 7 live Ollama tests skipped. Real-model behaviour on
  Windows telemetry is unknown.
- **Wazuh**: NOT VERIFIED live (unchanged; now an optional integration).

## Known limitations

- Benign closure still requires a recognized endpoint-management agent (Intune IME,
  ConfigMgr) as the alerted process's parent. On an unmanaged PC, legitimate activity
  ends as `insufficient_evidence` (RW-02 expectation). Extending this safely (signer and
  hash verification) is the main open product decision.
- Without Sysmon, process ancestry and network activity cannot be established; Security
  4688 is a degraded fallback (no GUIDs). Benign is never granted in that state.
- Capability discovery infers "limited" from the absence of recent events and does not
  query service state; a Sysmon service stopped minutes ago can still look active.
- The host-signal requirement blocks benign while any other signal exists within the
  investigation window (conservative; RW-02 must be run ≥ 60 min apart from others).
- Host-level contradictions are only as complete as the signal rules and the scan cap
  (2,000 newest events per source; a hit is disclosed as a note that fails the check).
- Only the local computer is investigated; no multi-endpoint support.
- Signal rules are intentionally few and simple; they are starting points, not detection
  coverage.
- The benchmark and all Windows samples are synthetic.
