# Changelog

## 0.3.1 — Reasoning-contract repair (2026-09-30)

Driven by two live `qwen2.5:7b-instruct` runs on v0.3
(`docs/validation/v0.3/live_ollama_runs/`). The gates held, but the model:

* tagged every finding `benign_administration`;
* invented an argument value;
* looped on answered requests;
* never collected host context or network.

This release repairs the model contract. **No gate, requirement, evidence rule or
security control was loosened.** Evidence: `docs/validation/v0.3.1/`. Release notes:
[V0.3.1_RELEASE_NOTES.md](V0.3.1_RELEASE_NOTES.md). **Real-model effect NOT VERIFIED**
(no Ollama in the development environment).

### Added
- Behavior-only claim definitions (`attack.CLAIM_DEFINITIONS`): label, meaning, what it
  does not mean, typical evidence. Intent and outcome are never asserted.
  `credential_theft` = LSASS credential-dumping behavior; `account_compromise` =
  possible compromise pattern. Wire values unchanged (decision recorded in the release
  notes).
- `claim_eligibility` / `technique_eligibility`, computed with the validator's own
  predicates. The assessment prompt carries a `claim_contract` and `attack_contract`:
  eligible items with citable IDs, unsupported items, items never supported here, and
  an explicit `benign_administration` warning.
- A tool argument contract generated from the Pydantic schemas: allowed values,
  ranges, defaults, prerequisites, a valid example per tool, and an argument glossary.
- Decide-step feedback: `last_step_result`, `answered_requests`,
  `collection_checklist` and `suggested_next_steps`. It is compacted under context
  pressure.
- Baseline collection. Host context and the trigger's process tree are collected by
  the application before the model's first step (`baseline_collection`, default on).
  Failures are visible failed collections.
- One bounded validation-feedback revision (`validation_revision`, default on). It uses
  application-generated feedback only and passes through the same gates. Recorded in
  `InvestigationReport.revision`.
- `ValidationResult.draft_verdict`, `proposed_claims` and `proposed_attack_techniques`.
  Exports gain "Model draft vs. accepted" and "Validation-feedback revision" sections.
- CLI `acceptance [--alerts] [--repeats] [--out] [--json]`, which applies the amended
  behavior-based criteria. `benchmark --repeats`. Per-run reasoning-contract
  diagnostics.
- `tests/test_reasoning_contract.py` (26 tests), including scripted replays of the
  observed qwen behaviour. Mutation set `docs/validation/v0.3.1/mutate_v031.sh` (C1–C11).

### Fixed
- **`model_visibility` counted omitted records as seen** at compaction level ≥3 when
  fewer than 12 records were retrieved (present since 0.3.0). At num_ctx 8192, INC-005
  closed benign with its child process and network connection unseen. The "shown in
  full" set is now capped at the records actually kept.
- Markdown exports rendered apostrophes as `&#x27;`.
- `get_logon_activity`, `get_powershell_activity` and `get_defender_activity` were
  missing from the coverage categories.

### Changed
- Tests whose premise is "the model never collected X" now run with
  `baseline_collection=False`. A baseline-aware variant was added.

## 0.3.0 — Standalone Windows investigator (2026-09-30)

Product direction: a local-first AI security investigation agent **for Windows**. The
default path needs no Wazuh, VM, SSH, SIEM or cloud service. The investigation engine
(bounded loop, application-owned evidence, validation, verdict gates, audit trace)
is unchanged in structure; a new backend implements the existing interface.
Evidence: `docs/validation/v0.3/`. **Not yet run on a real Windows machine.**

### Added
- **WindowsEventBackend** (`backends/windows.py`, `windows_events.py`,
  `winevt_reader.py`): read-only access to Sysmon, Windows Security, PowerShell
  Operational and Microsoft Defender Operational via `EvtQuery`/`EvtNext`/`EvtRender`
  (pywin32, Windows only); normalization of the supported event IDs; application-built,
  allowlisted `ChannelQuery` → XPath; capability discovery (active / limited / not
  installed / access denied); local-host-only queries; PID→GUID correlation for
  PowerShell script blocks; local host context.
- `windows-replay` backend: recorded Windows event XML (tests; offline replay of a real
  machine's `wevtutil` exports, UTF-8 or UTF-16). Packaged **synthetic** samples
  (`investigator/windows_samples/`, generated by `build_windows_samples.py`).
- **Deterministic signals** (`signals.py`): Defender detection, LSASS memory access,
  persistence (4698 / Run keys), Office → script interpreter, interpreter → commonly
  abused binary, suspicious PowerShell, failed-logon burst.
- Tools: `get_logon_activity`, `get_powershell_activity`, `get_defender_activity`;
  `get_network_activity(scope="process_tree")`. Claims `security_product_detection`,
  `suspicious_script`. Categories `script`, `detection`, `privilege`, `process_termination`.
- CLI `sources` (capability discovery), `--backend windows|windows-replay`,
  `--replay-dir`; `diagnose` for the Windows backends; dashboard system status and
  telemetry sources; product rename to *Investigator*.
- Real-world validation kit: `docs/validation/v0.3/REAL_WORLD_PROCEDURE.md`,
  `rw_scenarios.ps1`, `capture_evidence.ps1`, `RESULTS.md` (NOT RUN).
- Opt-in live Windows integration tests (`SOCI_IT_WINDOWS=1`, Windows only).
- Static test: no subprocess/registry/service/process-control/Defender/firewall/
  file-deletion/log-clearing API anywhere in the package.

### Changed (deliberate changes to v0.2.1 gate semantics, driven by real-telemetry volume)
- **Capped exploratory queries** no longer mark the run `incomplete`; they stay in the
  coverage ledger (truncated count, known unknowns, verification steps). Required
  collection is still judged strictly (a truncated requirement query never counts).
  Reason: on a real Windows host every host-wide ±15/60-minute query exceeds 25 records,
  which made `benign` unreachable for every alert.
- New requirement **`host_signals`** compensates: no other deterministic signal on the
  host within the investigation window, checked over the host's telemetry (not via
  capped model queries); an incomplete scan fails it.
- **`network_activity`** may be met by a complete tree-scoped query covering every
  process of the alerted tree (as it stands at report time), besides a complete
  host-wide query.
- **`model_visibility`** is judged on priority evidence (trigger, alerted process tree,
  records with contradiction/suspicion indicators). Routine records outside the tree
  that do not fit the prompt are disclosed as a known unknown instead of making the run
  incomplete. Hidden priority evidence still makes it incomplete and blocks `benign`.
- Tree contradictions add `suspicious_script_content`; host contradictions add
  `defender_detection`. Prompts include each record's `parent_process_guid`.
- Malformed model-supplied query values are rejected calls (`invalid_argument`), not
  telemetry failures. `health` prints classified errors only.

### Found and fixed while bringing the pipeline up on Windows-shaped data
(first attempts that failed, kept for the record)
- Every replay investigation was `incomplete` / never benign: host-wide queries capped
  → led to the truncation/host_signals change above.
- A process-scoped query returned **all** Defender events (source without process
  identity was not filtered) → an unrelated detection 3 h earlier entered the evidence.
  Such sources are now skipped for process-scoped queries (`V6` mutation test).
- PID→GUID mapping for script blocks was bounded by the half-window end and missed a
  process created exactly at the alert time.
- Security records produced misleading "cannot filter by process" gaps on
  process-scoped queries; now a gap only when that category was explicitly requested.
- Defender 1116 + 1117 for one detection produced two signals; now one.

### Tests
328 passed (+4 optional real-tokenizer tests) vs 279 in 0.2.1; 47 Windows backend /
requirement tests; 10 new mutation checks (all killed); the 11 v0.2.1 guards remain
killed on 0.3.0.

## 0.2.1 — Investigation integrity fix (2026-09-30)

Narrowly scoped to the findings in [REVIEW_FOLLOWUP.md](REVIEW_FOLLOWUP.md) (F1–F11).
No new product features, no architecture changes, no remediation. All R1–R18 fixes
from 0.2.0 are preserved. Evidence: `docs/validation/v0.2.1/`.

### Verdict integrity
- **Benign must be earned (F1).** New `CollectionRequirement` ledger
  (`report.coverage.requirements`), computed by application code from each tool
  call's resolved target (`ToolCall.target`), never from model prose:
  `process_tree` (the alerted process's ancestry + descendants; a parent outside the
  retained window is acceptable, a missing target or truncation is not),
  `network_activity` (host-wide, not truncated, covering ±15 min of the alert),
  `host_context` (found for the alerted host, no instruction-like text),
  `model_visibility` (the assessment prompt showed every retrieved record in full and
  no prompt overflow was suspected). Any unmet requirement withholds benign →
  `insufficient_evidence`. The model may still propose benign.
- **Descendant-aware guard (F2).** `get_process_tree` walks all descendant
  generations breadth-first (bounded: 8 generations, the per-tool result limit;
  reaching a bound is truncation). The benign guard evaluates every record performed
  by the alerted process or any descendant, via a cycle-safe fixed-point closure over
  retrieved parent links (same host only). Cyclic relationships mark the tree
  untrustworthy.
- **Host-context injection (F4).** Asset metadata is screened like telemetry; the flag
  is recorded on the tool call, shown to the model as `injection_suspected`, fails
  the `host_context` requirement, and blocks benign. Instruction-like alert fields
  (title, user, host) also block benign.

### Context-size safety (F3)
- New `investigator/compaction.py`. Base64 (with UTF-16LE/PowerShell detection), hex
  (≥130 chars, so MD5–SHA-512 hashes stay verbatim), high-entropy tokens and mostly
  non-ASCII text are replaced **in prompts only** by a bounded marker: type, length,
  decoded byte count, SHA-256 prefix, 12-char head/tail. URLs with a domain are kept
  verbatim. Evidence attributes, raw records and hashes are untouched.
- `prompt_chars_per_token` default 3.0 → **2.0**, capped at 2.0 (an older `.env` with
  3.0 is clamped, not rejected). The budget reserves `num_predict`, 256 template tokens
  and 1,400 tokens for a repair turn.
- Each exchange records `estimated_prompt_tokens`, `prompt_token_limit`,
  `blobs_compacted`, `evidence_summarized`. A pre-flight estimate over the limit, or a
  server-reported prompt ≥ 97% of `num_ctx` or above the prompt limit, sets
  `context_overflow_suspected`, adds a `context:` trace error, marks the report
  `incomplete`, and blocks benign.
- Attribute truncation at compaction levels ≥ 1 never cuts a compaction marker.

### Retrieval (F5)
- Time-centered retrieval for `search_events`, `get_related_events`,
  `get_network_activity` and `get_process_details`: the nearest events before and
  at/after the anchor are fetched separately (`EventQuery.order`, honoured by the
  fixture and Wazuh backends) and balanced; unused quota on one side goes to the other.
  Truncation gaps state what was kept.

### Other
- **Cancellation (F7):** a cancel accepted during the final-report call now ends the
  run `cancelled` (draft discarded, still audited); repairs stop once cancelled.
- **Shutdown race (F11):** the running→interrupted transition happens under the run lock.
- **Evaluation (F9):** benchmark output compares the agent with an always-`suspicious`
  baseline and adds integrity metrics (benign TP/FP, escalation TP/FN,
  insufficient-evidence count, required-evidence recall, unsupported claims,
  evidence-reference validity, coverage requirements met, context-overflow and
  incomplete counts). The legacy "fully correct" headline is kept and labelled.
  `--adversary benign-after-investigation|benign-immediately` runs evaluation-only
  benign proposers. 4 new cases (BM-X08, M06, X09, B05), truth committed first.
- **Hygiene (F10):** browser tests only rewrite tracked screenshots with
  `SOCI_UPDATE_SCREENSHOTS=1`.
- Tests: 228 → 279 (+4 real-tokenizer tests, skipped unless `SOCI_TOKENIZER_JSON`).

### Behaviour changes to note
- Fewer benign closures when collection is thin: an investigation that never queried
  the tree, host-wide network activity or asset context can no longer end `benign`.
  Mock benchmark: benign TP unchanged (2/7: BM-B01, BM-B05); X09 no longer benign.
- `SOCI_OLLAMA_NUM_CTX` below 8192 cannot hold the minimal prompt at 2 chars/token.
- Each retrieval tool issues two backend queries (before/after the anchor) per category.
